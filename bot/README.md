# 예천군 디스코드 봇

Node.js(discord.js v14)로 만든 디스코드 봇입니다. 두 가지 기능이 들어 있습니다.

1. 로블록스 계정 인증
2. 문의 티켓 시스템 (HTML 기록 저장 포함)

봇이 보내는 모든 메시지는 임베드로만 구성되어 있고, 버튼과 드롭다운은 항상 임베드에 붙어서 나갑니다.
봇이 만들어내는 문구에는 이모티콘을 쓰지 않습니다.

---

## 1. 로블록스 계정 인증

인증 패널은 봇이 실행될 때 `1418823709027733517` 채널에 자동으로 게시됩니다.

진행 순서

1. 사용자가 패널의 **인증 시작** 버튼을 누릅니다. (`/인증` 명령으로도 같은 창이 열립니다.)
2. 창에 로블록스 닉네임을 입력하면, 봇이 `YCC-123` 형식(알파벳 3자 + 숫자 3자)의 코드를 임베드로 보내 줍니다.
3. 사용자가 그 코드를 로블록스 프로필 **소개란(About)** 에 붙여넣고 저장합니다.
4. 코드를 보내 준 임베드 아래의 **인증 확인** 버튼을 누릅니다.
5. 봇이 로블록스 API로 소개란을 읽어 코드가 있는지 확인하고, 확인되면
   - 서버 별명을 `예천군 시민ㅣ로블록스닉네임` 으로 변경하고
   - `1418823708247720077` 역할을 지급합니다.

세부 동작

- 코드는 발급 후 30분간 유효하며, 임베드 아래의 **코드 재발급** 버튼으로 새로 받을 수 있습니다.
- 코드 대조는 대소문자와 하이픈, 공백 차이를 무시합니다. (`ycc123`, `YCC 123` 모두 인정)
- 헷갈리기 쉬운 `I`, `O` 는 코드에 쓰지 않습니다.
- 이미 다른 디스코드 계정이 연동한 로블록스 계정은 다시 연동할 수 없습니다.
- 별명 변경이나 역할 지급이 실패해도 어느 쪽이 실패했는지 임베드에 그대로 알려 줍니다.
  (서버 소유자이거나 봇보다 높은 역할을 가진 사람은 별명을 바꿀 수 없습니다.)

## 2. 티켓 시스템

티켓 패널은 봇이 실행될 때 `1535140042652254219` 채널에 자동으로 게시됩니다.

- 드롭다운 항목은 **통합문의 / 버그문의 / 파트너문의** 세 가지입니다.
- 항목을 고르면 `1535141065160658944` 카테고리 아래에 채널이 만들어집니다.
  이름은 종류별로 따로 번호가 매겨집니다. `통합문의-0001`, `버그문의-0001`, `파트너문의-0001`
- 만들어진 채널은 **작성자 본인** 과 `1535140290581635162` (스태프) 역할만 볼 수 있습니다.
- 같은 종류의 티켓은 한 사람당 하나만 열 수 있습니다.
- 채널 맨 위에 고정되는 임베드에 **티켓 닫기** 버튼이 있습니다. 이 버튼은 스태프 역할 보유자와 관리자만 쓸 수 있습니다.

티켓을 닫으면

1. 확인 창이 한 번 뜹니다. (채널 삭제는 되돌릴 수 없기 때문입니다.)
2. 채널의 모든 메시지를 모아 HTML 기록 파일을 만듭니다.
   - 텍스트 (굵게, 기울임, 밑줄, 취소선, 스포일러, 인용문, 코드블록)
   - 이미지, 동영상, 음성, 그 밖의 첨부파일
   - 링크 (본문에서 자동으로 찾아 목록으로도 정리)
   - 멘션, 커스텀 이모지, 답장 대상, 수정됨 표시, 임베드, 스티커
   - 만들어진 시간, 닫힌 시간, 유지 시간, 작성자, 닫은 사람, 참여자 목록
3. 기록 파일을 `1535140618626670623` 채널에 요약 임베드와 함께 보냅니다.
4. 5초 뒤에 티켓 채널을 삭제합니다.

디스코드 첨부파일 링크는 시간이 지나면 만료되기 때문에, 이미지와 동영상은 가능한 한 HTML 파일 안에
직접 넣습니다. 그래서 나중에 파일을 열어도 그대로 보입니다. 용량이 큰 파일은 원본 링크만 남고,
그 사실이 기록 안에 표시됩니다.

## 설치

Node.js 18.17 이상이 필요합니다. (개발 및 확인은 Node 22에서 했습니다.)

```bash
cd bot
npm install
cp .env.example .env
```

`.env` 파일을 열어 `DISCORD_TOKEN` 을 채웁니다. 채널과 역할 ID는 요청받은 값이 기본으로 들어 있어
그대로 두면 됩니다. 바꾸고 싶으면 `.env` 에서 덮어쓰면 됩니다.

```bash
npm start
```

## 디스코드 개발자 포털 설정

**Bot 탭에서 아래 두 가지를 반드시 켜 주세요.**

- `SERVER MEMBERS INTENT` - 별명 변경과 역할 지급에 필요합니다.
- `MESSAGE CONTENT INTENT` - 티켓 기록에 메시지 본문을 담기 위해 필요합니다. 꺼져 있으면 기록이 빈 내용으로 저장됩니다.

## 봇에게 필요한 권한

| 권한 | 쓰이는 곳 |
| --- | --- |
| 채널 보기 / 메시지 보내기 / 링크 첨부 / 파일 첨부 | 패널 게시, 기록 전송 |
| 메시지 기록 보기 | 기록 생성, 기존 패널 정리 |
| 채널 관리 | 티켓 채널 생성 및 삭제 |
| 역할 관리 | 인증 역할 지급 |
| 별명 관리 | 인증 시 별명 변경 |
| 메시지 관리 | 티켓 안내 메시지 고정 |

역할 순서도 중요합니다. **봇의 역할이 `예천군 시민` 역할보다 위에 있어야** 역할을 지급할 수 있고,
인증하는 사람보다 위에 있어야 별명을 바꿀 수 있습니다.

## 슬래시 명령

| 명령 | 설명 | 권한 |
| --- | --- | --- |
| `/인증` | 인증 창을 엽니다. | 모두 |
| `/인증패널` | 인증 패널을 다시 게시합니다. | 서버 관리 |
| `/티켓패널` | 티켓 패널을 다시 게시합니다. | 서버 관리 |

## 설정 항목

`.env` 로 바꿀 수 있는 값들입니다. 비워 두면 괄호 안의 기본값이 쓰입니다.

| 이름 | 설명 |
| --- | --- |
| `VERIFY_PANEL_CHANNEL_ID` | 인증 패널 채널 (1418823709027733517) |
| `VERIFIED_ROLE_ID` | 인증 완료 역할 (1418823708247720077) |
| `NICKNAME_PREFIX` | 별명 앞에 붙일 문구 (예천군 시민ㅣ) |
| `VERIFY_CODE_TTL_MINUTES` | 인증 코드 유효 시간 (30) |
| `TICKET_PANEL_CHANNEL_ID` | 티켓 패널 채널 (1535140042652254219) |
| `TICKET_STAFF_ROLE_ID` | 스태프 역할 (1535140290581635162) |
| `TICKET_TRANSCRIPT_CHANNEL_ID` | 기록 전송 채널 (1535140618626670623) |
| `TICKET_CATEGORY_ID` | 티켓 카테고리 (1535141065160658944) |
| `TICKET_DELETE_DELAY_SECONDS` | 기록 전송 후 채널 삭제까지 대기 시간 (5) |
| `TRANSCRIPT_MAX_MESSAGES` | 기록에 담을 최대 메시지 수 (5000) |
| `TRANSCRIPT_INLINE_MAX_BYTES` | HTML 안에 넣을 개별 파일 최대 크기 (2MB) |
| `TRANSCRIPT_INLINE_TOTAL_BYTES` | HTML 안에 넣을 파일 총 용량 (6MB) |
| `DATA_FILE` | 티켓 번호와 인증 정보 저장 경로 (./data/store.json) |

## 파일 구조

```
bot/
  src/
    index.js                 봇 시작, 상호작용 라우팅, 슬래시 명령 등록
    config.js                설정값과 티켓 종류 정의
    features/
      verification.js        로블록스 인증 (패널, 창, 코드 확인, 별명/역할 처리)
      tickets.js             티켓 생성과 종료
      transcript.js          HTML 기록 생성
    roblox/
      api.js                 로블록스 API 호출
      code.js                인증 코드 생성과 대조
    util/
      config, embeds, log, panel, store, time
```

## 데이터 저장

`data/store.json` 에 티켓 번호 카운터, 열려 있는 티켓, 인증 정보가 저장됩니다.
이 파일을 지우면 티켓 번호가 처음부터 다시 시작하니 주의해 주세요.
쓰기는 임시 파일에 먼저 저장한 뒤 이름을 바꾸는 방식이라 도중에 꺼져도 파일이 깨지지 않습니다.
