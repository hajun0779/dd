# RoStation 봇

Node.js(discord.js v14)로 만든 디스코드 봇입니다.
문의, 후기, 제품 전달, 안내, 업무 배당, 급여를 담당합니다.

봇이 보내는 모든 메시지는 **Components V2 컨테이너**로 만들어집니다.
제목, 본문, 구분선, 이미지, 버튼, 드롭다운, 꼬리말이 전부 한 상자 안에 들어갑니다.
(클래식 임베드는 버튼을 안에 넣을 수 없고 항상 임베드 바깥 아래에 붙습니다.)
봇이 만들어내는 문구에는 이모티콘을 쓰지 않습니다.
모든 컨테이너 맨 아래에는 `Copyright 2026. RoStation. All rights reserved.` 가 붙습니다.

## 문의 시간

```
평일 AM 11:00 ~ PM 06:00
```

이 시간 안에 올라온 문의는 문의 채널에서 **스태프 역할을 부릅니다.**
시간 밖에 올라온 문의는 역할을 부르지 않고, 문의 시간에 답변한다는 안내만 남깁니다.

시간은 한국 시간 기준입니다. `.env` 에서 바꿀 수 있습니다.

시간대는 `Intl` 에 기대지 않고 UTC 에 9시간을 더해 직접 계산합니다.
호스팅에 따라 Node 가 전체 ICU 없이 설치되어 있으면 `Asia/Seoul` 이 무시되고 UTC 로 처리되는데,
그러면 낮 12시가 새벽 3시로 읽혀 문의 시간 판정이 어긋나기 때문입니다.
한국은 서머타임이 없어 더하기만으로 정확합니다.

봇을 켜면 로그에 지금 한국 시간과 문의 시간 안인지 여부가 찍히니 확인해 보실 수 있습니다.

## 문의 종류

종류마다 카테고리가 따로 있습니다.

| 종류 | 채널 이름 | 카테고리 설정 |
| --- | --- | --- |
| 통합 문의 | `통합문의-0001` | `TICKET_CATEGORY_GENERAL` |
| 제품 문의 | `제품문의-0001` | `TICKET_CATEGORY_PRODUCT` |

**제품 문의와 파트너 문의 카테고리 ID 를 아직 넣지 않았습니다.**
`.env` 에 넣기 전까지는 세 종류가 통합 문의 카테고리를 같이 씁니다. (봇을 켜면 로그로 알려 줍니다.)

## 문의를 닫으면

1. 확인 창이 한 번 뜹니다. (채널 삭제는 되돌릴 수 없기 때문입니다.)
2. 채널의 모든 메시지를 모아 HTML 기록 파일을 만듭니다.
   - 텍스트 (굵게, 기울임, 밑줄, 취소선, 스포일러, 인용문, 코드블록, 제목)
   - 이미지, 동영상, 음성, 그 밖의 첨부파일
   - 링크 (본문에서 자동으로 찾아 목록으로도 정리)
   - 멘션, 커스텀 이모지, 답장 대상, 수정됨 표시, 임베드, 스티커, Components V2 컨테이너
   - 접수 시간, 닫힌 시간, 유지 시간, 작성자, 닫은 사람, 참여자 목록
3. 기록 파일을 `1535140618626670623` 채널에 올립니다.
4. 5초 뒤에 문의 채널을 삭제합니다.

디스코드 첨부파일 링크는 시간이 지나면 만료되기 때문에, 이미지와 동영상은 가능한 한 HTML 파일 안에
직접 넣습니다. 그래서 나중에 파일을 열어도 그대로 보입니다. 용량이 큰 파일은 원본 링크만 남고,
그 사실이 기록 안에 표시됩니다.

## 실행

이 봇은 exe 파일이 아니라 Node.js 프로그램입니다. 실행 진입점은 `index.js` 입니다.
먼저 [nodejs.org](https://nodejs.org) 에서 **Node.js LTS** 를 설치해 주세요. (18.17 이상이 필요합니다.
개발과 확인은 Node 22에서 했습니다.)

Components V2 를 쓰므로 `discord.js` 는 **14.19.0 이상**이 필요합니다.
`package.json` 에 그렇게 적혀 있으니 `npm install` 만 하면 됩니다.

1. `bot` 폴더에서 라이브러리를 설치합니다. 처음 한 번만 하면 됩니다.

   ```bash
   cd bot
   npm install
   ```

   설치되는 것은 `discord.js` 하나뿐입니다.

2. `config.js` 를 메모장으로 열고, 맨 위 `BOT_TOKEN` 의 따옴표 사이에 봇 토큰을 붙여넣고 저장합니다.

   ```js
   const BOT_TOKEN = '여기에 토큰을 붙여넣으세요';
   ```

3. 실행합니다.

   ```bash
   npm start        # node index.js 와 같습니다
   ```

끌 때는 `Ctrl + C` 를 누르면 됩니다.

### .env 파일을 쓰고 싶다면

토큰을 소스 파일에 두기 싫으면 `bot` 폴더에 `.env` 파일을 만들어도 됩니다.
`.env.example` 을 복사해서 쓰면 편합니다. `.env` 값이 `config.js` 의 `BOT_TOKEN` 보다 우선합니다.

```bash
cp .env.example .env    # 그리고 DISCORD_TOKEN 을 채웁니다
```

별도 라이브러리 없이 봇이 직접 읽으므로 `dotenv` 같은 걸 설치할 필요는 없습니다.

### 토큰 주의사항

`config.js` 에 토큰을 넣었다면 **그 파일을 깃허브에 올리거나 남에게 보내지 마세요.**
토큰이 새면 다른 사람이 봇을 마음대로 조종할 수 있습니다.
이미 샜다면 디스코드 개발자 포털에서 `Reset Token` 을 눌러 새로 발급받으면 됩니다.
소스를 공유할 일이 있다면 `.env` 방식을 쓰는 편이 안전합니다. (`.env` 는 `.gitignore` 에 들어 있습니다.)

### 프테로닥틸(Pterodactyl) 호스팅에 올릴 때

파일은 `bot` 폴더째로 올리지 말고, **`bot` 폴더 안의 내용물을 `/home/container` 바로 아래**에
올려 주세요. `package.json` 과 `index.js` 가 `/home/container/package.json`,
`/home/container/index.js` 가 되어야 합니다.

그리고 패널 **Startup** 탭에서 `MAIN_FILE` 값을 정확히 아래처럼 바꿔 주세요.

```
*.js
```

`index.js` 가 아니라 `*.js` 입니다. 오타가 아닙니다.

이유는 이렇습니다. 많이 쓰이는 Node.js 에그의 시작 명령이 이렇게 되어 있습니다.

```bash
if [[ "${MAIN_FILE}" == "*.js" ]]; then node ... ; else ts-node --esm ... ; fi
```

오른쪽 `"*.js"` 에 따옴표가 붙어 있어서 패턴 비교가 아니라 **글자 그대로의 비교**가 됩니다.
그래서 `MAIN_FILE` 이 `index.js` 면 조건이 항상 거짓이 되고, 봇이 `node` 가 아니라 `ts-node` 로
실행됩니다. 그 `ts-node` 는 컨테이너에 typescript 가 없어서 시작하자마자 아래처럼 죽습니다.

```
TypeError: Cannot read properties of undefined (reading 'fileExists')
    at readConfig (/usr/local/lib/node_modules/ts-node/dist/configuration.js:91:33)
```

`MAIN_FILE` 을 `*.js` 로 두면 조건이 참이 되고, 같이 들어 있는 `*.js` 파일이 `index.js` 를
불러오는 역할을 합니다. 그래서 정상적으로 `node` 로 실행됩니다.

패널에서 **시작 명령(Startup Command) 자체를 고칠 수 있다면** 그게 더 깔끔합니다.
그때는 `MAIN_FILE` 을 `index.js` 로 두고 시작 명령을 아래처럼 바꾸면 됩니다.
(`*.js` 파일은 그냥 두어도 아무 문제 없습니다.)

```bash
/usr/local/bin/node /home/container/index.js
```

### 24시간 켜 두려면

창을 닫으면 봇도 꺼집니다. 항상 켜 두려면 PC를 계속 켜 두거나,
서버 호스팅에 올려서 `pm2` 같은 도구로 실행하는 방법이 있습니다.

```bash
npm install -g pm2
pm2 start index.js --name rostation-bot
pm2 save
```

## 디스코드 개발자 포털 설정

**Bot 탭에서 아래 두 가지를 반드시 켜 주세요.**

- `MESSAGE CONTENT INTENT` - 기록에 메시지 본문을 담는 데 필요합니다. 꺼져 있으면 기록이 빈 내용으로 저장됩니다.
- `SERVER MEMBERS INTENT` - 직원 명단에서 역할별 인원을 세고, 서버에 들어온 사람을 맞이하는 데 필요합니다.

## 문의 안내

```
/문의안내
/문의안내 채널:#문의안내
```

`채널` 을 고르면 그 채널에, 비우면 명령을 쓴 채널에 올라갑니다.

```
문의 안내

제품 문의를 통해 주문 제작 신청이 가능합니다!
현재 로블록스 애셋 및 맵 주문 제작과 디스코드 봇 외주 문의를 주로 받고 있습니다.
주문 제작이 필요하신 경우 제품 문의 티켓을 열어주세요.
──────────────
제휴 문의도 언제든지 받고 있습니다!
서버 간 파트너십 및 제휴를 희망하시는 경우 파트너 문의 티켓을 열어주시면 확인 후 안내드리겠습니다.
──────────────
문의 가능 시간이 지나거나 문의 시간 이전에 티켓을 생성하실 경우 운영팀에게 별도의 멘션 알림이 전송되지 않습니다.
빠른 확인과 처리를 원하신다면 가급적 문의 가능 시간 내에 티켓을 생성해 주시기 바랍니다.
──────────────
문의 가능 시간
평일 AM 11:00 ~ PM 06:00
```

문단 사이는 컨테이너의 구분선으로 나눕니다.
맨 아래 문의 가능 시간은 문의 시간 설정을 그대로 따라갑니다.

### 문단 더하기

명령으로 문단을 더할 수 있습니다. 코드를 고치지 않아도 됩니다.

```
/문의안내추가 내용:환불은 제품 전달 전까지만 가능합니다.
/문의안내추가 내용:첫 줄입니다.\n둘째 줄입니다.
```

- 줄을 바꾸려면 `\n` 을 넣으면 됩니다.
- 더한 문단은 기본 문단 셋 **뒤에** 붙습니다.
- 더한 뒤에 `/문의안내` 를 다시 올려야 반영됩니다. (이미 올라간 글은 안 바뀝니다.)

```
/문의안내삭제 문단:1. 환불은 제품 전달 전까지만 가능합니다.
```

뺄 문단은 목록에서 골라집니다. 기본 문단 셋은 여기서 뺄 수 없고, `notice.js` 의
`TICKET_NOTICE` 를 고쳐야 합니다.

더한 문단은 보관 채널(`STORAGE_CHANNEL_ID`)에 메시지로 남아서 봇을 다시 켜도 그대로 있습니다.
보관 채널이 없으면 기본 문단 셋만 올라갑니다.

## 이용약관

`/이용약관` 을 쓰면 그 채널에 약관이 올라갑니다.
내용은 `terms.js` 맨 위의 목록을 고치면 바뀝니다.

## A/S 이용약관

`/수리약관` 을 쓰면 그 채널에 A/S 약관이 올라갑니다.

- 제작이 끝나고 전달이 끝난 시점부터 **24시간** 안에 수리를 맡길 수 있습니다.
- 무상 수리는 **인당 최대 2회**입니다.
- 24시간이 지났거나 2회를 다 쓴 뒤에는 약간의 비용을 부담해야 합니다.
- 새 기능 추가나 요청하지 않았던 변경은 A/S 가 아니라 새 작업으로 봅니다.
- 이용자가 직접 수정한 뒤 생긴 문제는 무상 수리 대상이 아닙니다.

기간과 횟수는 `.env` 의 `REPAIR_HOURS`, `REPAIR_FREE_COUNT` 로 바꿀 수 있습니다.
문장 자체를 고치려면 `terms.js` 의 `REPAIR_TERMS` 목록을 고치면 됩니다.

## 채용 공고

```
/채용공고 팀:개발팀 인원:2 접수기간:7일
/채용공고 팀:마케팅팀 인원:1 접수기간:2026-08-20 23:59 모두멘션:True
```

팀과 인원, 접수 기간만 고르면 나머지는 알아서 채워져서 그 채널에 올라갑니다.

```
개발팀 채용
RoStation 에서 개발팀과 함께하실 2명을 모집합니다.
의뢰받은 제품을 만들어 주실 분을 찾습니다.

모집 인원   2명
하는 일     - 로블록스 스크립트 작성과 수정
            - 의뢰받은 제품 제작
            - 전달한 제품의 A/S
지원 자격   - 직접 만들어 보신 작업물을 보여 주실 수 있는 분
            - 맡은 일을 기한 안에 마치실 수 있는 분
            - 작업 상황을 중간에 알려 주실 수 있는 분
우대 사항   - 팀으로 작업해 보신 분
            - 스튜디오 협업(Team Create)에 익숙하신 분
지원 방법   아래 접수하기 버튼을 눌러 지원서를 작성해 주세요.
접수 기간   2026-08-16 (일) 오후 11:59 까지
문의 시간   평일 AM 11:00 ~ PM 06:00

[접수하기]  [문의 채널로 가기]
```

`모두멘션` 을 켜면 `@everyone` 이 함께 나갑니다. 끄면 멘션 알림이 울리지 않습니다.
문의 시간은 문의 시간 설정을 그대로 따라갑니다.

### 접수하기

**접수하기** 를 누르면 지원서 창이 열립니다.

| 칸 | 내용 |
| --- | --- |
| 자기소개 | 이름 또는 별명, 나이대, 해 오신 일 |
| 포트폴리오 | **개발팀은 구글 드라이브 링크 필수**, 다른 팀은 선택 |
| 활동 가능 시간 | 예: 평일 오후 7시 ~ 11시 |
| 지원 동기 | 왜 지원했는지 |
| 열심히 할 의향이 있으신가요 | |

- 개발팀 지원서는 `https://drive.google.com/...` 또는 `https://docs.google.com/...` 링크만 받습니다.
  다른 주소를 넣으면 접수되지 않고 다시 적어 달라고 안내합니다.
- 접수 기간이 지나면 버튼이 **접수 마감** 으로 잠기고, 눌러도 창이 열리지 않습니다.
- 낸 지원서는 `RECRUIT_CHANNEL_ID` 채널에 올라갑니다.
  비워 두면 총관리자에게 DM 으로 갑니다.
- 지원한 사람에게는 접수됐다는 안내가 본인에게만 보이게 뜹니다.

같은 사람이 여러 번 내는 것은 막지 않습니다. 필요하시면 막아 드리겠습니다.

팀 목록과 문구는 `recruit.js` 맨 위의 `RECRUIT_TEAMS` 를 고치면 바뀝니다.
팀을 더하면 `/채용공고` 의 선택지에도 자동으로 들어갑니다. (최대 25개)

## 직원 명단

역할마다 직책과 별 개수를 등록해 두면, 그 역할을 가진 사람이 자동으로 명단에 들어갑니다.

```
/직원명단설정 추가  역할:@Head Director  직책:Head Director  별:5
/직원명단설정 추가  역할:@Director       직책:Director       별:4
/직원명단설정 추가  역할:@Manager        직책:Manager        별:2
/직원명단설정 추가  역할:@Secretary      직책:Secretary      별:1
```

`/직원명단` 을 쓰면 이렇게 나옵니다. 별이 많은 직책이 위로 갑니다.

```
[★★★★★]
Head Director - @사람

[★★★★]
Director - @사람

[★★]
Manager - @사람

[★]
Secretary - @사람
```

역할에 아무도 없으면 `공석` 으로 나옵니다.
역할별 인원을 세려면 개발자 포털에서 `SERVER MEMBERS INTENT` 를 켜야 합니다.

### 자동 갱신

`STAFF_LIST_CHANNEL_ID` 채널에는 명단이 **1시간마다 자동으로 갱신**됩니다.
새 글을 올리지 않고 같은 글을 고쳐 쓰기 때문에 채널이 지저분해지지 않습니다.
역할을 주거나 뺐을 때 다음 갱신에 반영되고, 맨 아래에 갱신 시각이 적힙니다.

주기는 `STAFF_LIST_REFRESH_MINUTES` 로 바꿀 수 있습니다. (최소 5분)

## 환영 메시지

서버에 사람이 들어오면 `WELCOME_CHANNEL_ID` 채널에 컨테이너가 올라갑니다.

```
개발1번출구, 로스테이션으로 오신걸 환영합니다.
로스테이션에 @들어온사람 님이 승차하셨습니다.
[그림]
```

제목은 `WELCOME_TITLE`, 설명은 `WELCOME_DESCRIPTION` 으로 바꿀 수 있습니다.
설명의 `{user}` 자리에 들어온 사람 멘션이 들어갑니다.

그림은 `WELCOME_IMAGE_URL` 주소에서 봇이 켜질 때 한 번 받아 옵니다.
디스코드 첨부 주소는 시간이 지나면 만료되므로, 받아 온 파일을 보관 채널
(`STORAGE_CHANNEL_ID`)에 옮겨 두고 그 뒤로는 그 파일을 붙여서 올립니다.
그림을 바꾸려면 새 주소를 `WELCOME_IMAGE_URL` 에 넣고, 보관 채널에 있는
`welcome.png` 메시지를 지운 뒤 봇을 다시 켜 주세요.

들어온 사람을 세려면 개발자 포털에서 `SERVER MEMBERS INTENT` 를 켜야 합니다.
봇이 들어왔을 때는 올리지 않습니다. 봇도 맞이하려면 `WELCOME_SKIP_BOTS=false` 로 바꾸세요.

## 초대 코드

```
/초대코드
```

봇이 **기간 무제한, 횟수 무제한** 초대를 하나 만들어서 본인에게만 보여 줍니다.
이미 만든 코드가 있으면 새로 만들지 않고 같은 코드를 다시 보여 줍니다.

그 코드로 누가 들어오면 **코드를 만든 사람에게 DM 으로 기록**이 갑니다.

```
초대 기록
@새로들어온사람 님이 회원님의 초대로 들어왔습니다.
코드        abc123
이 코드로 들어온 사람   3명
들어온 시간   2026-08-09 (일) 오후 01:20
```

`INVITE_LOG_CHANNEL_ID` 를 채우면 같은 내용이 그 채널에도 올라갑니다.

초대가 만들어질 채널은 `INVITE_CHANNEL_ID` 로 정합니다.
비우면 환영 채널을, 그것도 없으면 명령을 쓴 채널을 씁니다.

### 초대 랭킹

```
/초대랭킹
/초대랭킹 인원:20
```

명령을 쓴 채널에 순위표가 올라갑니다. 기본 10명이고 최대 25명까지 볼 수 있습니다.

```
초대 랭킹
1위  @사람  12명
2위  @사람  8명
3위  @사람  8명
5위  @사람  3명

전체        4명이 31명을 초대했습니다
내 순위      9위  @나  1명
```

인원이 같으면 순위도 같습니다. 위 예시처럼 2위가 둘이면 다음은 4위가 아니라 5위입니다.
한 사람이 코드를 여러 번 발급받았어도 전부 더해서 셉니다.
순위표에 이름이 올라도 멘션 알림은 울리지 않습니다.

### 어떻게 알아내나

디스코드는 "이 사람이 이 초대로 들어왔다" 를 알려 주지 않습니다.
그래서 봇이 서버의 초대 사용 횟수를 들고 있다가, 사람이 들어온 순간 다시 읽어서
횟수가 늘어난 초대를 찾습니다. 한도가 차서 사라진 초대도 찾아냅니다.

봇에게 **서버 관리** 권한과 **초대 링크 만들기** 권한이 있어야 합니다.
정확히 같은 순간에 두 명이 서로 다른 코드로 들어오면 구분할 수 없어서,
틀리게 적지 않고 기록을 남기지 않습니다.

## 파트너 안내

```
/파트너쉽 서버링크:https://discord.gg/... 제목:파트너 소개 소개글:... 모두멘션:True 사진:(업로드)
```

명령을 쓴 채널에 컨테이너로 올라갑니다. 안에 사진과 **서버 들어가기** 버튼이 들어갑니다.
`모두멘션` 을 켜면 `@everyone` 이 함께 나갑니다. 봇에게 모두에게 멘션 권한이 있어야 합니다.

## 후기

문의를 닫으면 문의를 남긴 사람에게, 제품을 받으면 받은 사람에게 **DM 으로 후기 요청**이 갑니다.

1. 별점 목록에서 1점부터 5점까지 고릅니다.
2. 고르면 후기를 적는 창이 열립니다.
3. 적어서 보내면 후기 채널(`REVIEW_CHANNEL_ID`)에 올라갑니다.

상대가 DM 을 닫아 두었으면 조용히 넘어갑니다. (로그에는 남습니다.)

## 제품

zip 파일만 등록할 수 있습니다.

```
/제품설정 등록  이름:내 제품  파일:(zip 업로드)  설명:설명글
/제품전송      제품:내 제품  유저:@사람
```

등록하면 봇이 zip 파일을 보관 채널(`STORAGE_CHANNEL_ID`)에 올려 둡니다.
`/제품전송` 을 하면 받는 사람에게 DM 으로 컨테이너가 가고, 그 안에 **제품 받기** 버튼이 있습니다.

**제품 받기** 를 누르면 그때 다운로드 주소를 새로 받아와 **다운로드** 버튼이 있는 화면을 보여 줍니다.
디스코드 첨부 링크는 시간이 지나면 만료되기 때문에, 미리 만들어 둔 주소를 넣지 않고 누를 때마다 새로
받아옵니다. 만료되면 **제품 받기** 를 다시 누르면 됩니다.

제품을 받고 나면 곧바로 제품 후기 요청이 DM 으로 갑니다.

`/제품설정` 과 `/제품전송` 은 `PRODUCT_APPROVAL_ROLE_ID` 역할이나 관리자만 쓸 수 있습니다.

## 총관리자

`ADMIN_ROLE_ID` 에 넣은 역할입니다. 모든 명령을 쓸 수 있고, 아래를 할 수 있습니다.

- 배당 상황 채널에서 **기간 조정** 버튼 누르기
- 급여 신청 채널에서 **지급 완료** 버튼 누르기
- 배당, 수락, 거절, 보고, 기간 조정, 연장, 기간 지남, 급여 지급을 **DM 으로 전부 보고받기**

## 업무 배당

### 1. 분야에 직원 넣기

분야는 목록에서 고릅니다. 자유 입력이 아닙니다.

```
Scripter   Builder   Graphic   Modeler   Animator
Programmer Clothing  GUI       Sound     VFX
```

```
/분야설정 등록  유저:@사람  분야:GUI  별명:지유아이 담당
```

분야를 늘리거나 이름을 바꾸려면 `config.js` 의 `WORK_FIELDS` 를 고치거나,
`.env` 에 `WORK_FIELDS=GUI,VFX,Builder` 처럼 쉼표로 적으면 됩니다. (최대 25개)

`/분야설정 목록` 은 사람이 없는 분야도 함께 보여 줍니다.

### 2. 배당하기

```
/배당 분야:GUI
```

목록이 뜨고, 직원을 고르면 창이 열립니다. **업무명 / 업무 설명 / 급여** 를 적으면

- 배당 목록 채널(`ASSIGN_LIST_CHANNEL_ID`)에 목록이 올라갑니다.
- 대상자에게 DM 으로 **해당 프로젝트를 맡으시겠습니까?** 가 갑니다.
  컨테이너 안에 **배당 수락** / **배당 거절** 버튼이 있습니다.

### 3. 수락과 거절

**배당 수락** 을 누르면 창이 열립니다.

- **기간** - `3일`, `48시간`, `2026-08-10 18:00` 처럼 적습니다. 한국 시간 기준입니다.
- **보고사항** - 진행 계획을 적습니다.

적어서 보내면 배당 상황 채널(`ASSIGN_STATUS_CHANNEL_ID`)에 올라가고,
그 글 안에 총관리자용 **기간 조정** 버튼이 들어갑니다.

**배당 거절** 을 누르면 사유를 적는 창이 열립니다. **10자 이상** 이어야 합니다.

### 4. 기간 조정

총관리자가 배당 상황 채널에서 **기간 조정** 을 누르면 새 기간과 사유를 적는 창이 열립니다.
대상자에게 DM 으로 **기간이 조정되었습니다** 가 가고, **수락** / **거절** 버튼이 있습니다.

- 수락하면 바로 새 기간이 적용됩니다.
- 거절하면 사유를 적습니다. 10자 이상이어야 하고, 기간은 그대로 유지됩니다.

### 5. 기간이 지나면

봇이 10분마다 확인합니다. 기간이 지난 배당은 **1시간마다** 대상자에게 DM 이 갑니다.

```
기간이 지났습니다
연장하시겠습니까?          [2시간 연장]
```

**연장** 을 누르면 2시간이 더 붙습니다.
한 번이라도 연장한 뒤에도 계속 기간을 넘기면, 알림이 갈 때마다 **경고가 1회씩 쌓입니다.**
(처음 기간을 넘겼을 때는 안내만 하고 경고는 붙지 않습니다.)

기간이 지난 것과 연장한 것은 배당 상황 채널에 올라가고, 총관리자에게 DM 으로도 갑니다.

### 6. 경고 상태

경고 상태 채널(`WARNING_CHANNEL_ID`)에 판이 하나 있고, 경고가 바뀔 때마다 그 판을 고쳐 씁니다.

```
직원 경고 상태
@사람 - 경고 3회
@사람 - 경고 1회
```

## 수리

배당한 프로젝트에 문제가 생겼을 때, 같은 방식으로 수리를 맡깁니다.

```
/수리 프로젝트:상점 시스템 분야:Scripter
```

`프로젝트` 칸은 지금까지 배당한 업무 목록에서 골라집니다. (직접 적지 않아도 됩니다.)
고르면 그 분야 직원 목록이 드롭다운으로 나오고, 사람을 고르면 창이 열립니다.

| 칸 | 내용 |
| --- | --- |
| 수리 항목 | 예: 상점 스크립트 오류 |
| 수리 내용 | 무엇이 어떻게 잘못됐는지 |
| 급여 | 예: 무료 또는 30,000원 |

보내면 담당자에게 DM 이 갑니다. **배당과 생김새가 같고 말만 다릅니다.**

```
해당 수리를 맡으시겠습니까?
상점 오류 수정

구매 버튼이 안 눌립니다.

프로젝트   상점 시스템
급여       무료
분야       Scripter

[수리 수락]  [수리 거절]
```

수락하면 기간을 적는 창이 열리고, 거절하면 사유를 적는 창이 열립니다.
그 뒤의 기간 조정, 연장, 기간 지남 알림, 경고까지 **배당과 똑같이 이어집니다.**

수리 기록은 배당 기록과 같은 곳에 저장되고, 안에 `kind: "repair"` 와 원래 프로젝트 이름이 함께 들어갑니다.
`/수리` 의 프로젝트 목록에는 배당만 나오고 수리는 나오지 않습니다.

## 급여

```
/급여지급 급여:100,000원 직원:@사람
```

직원에게 DM 으로 **급여가 도착했습니다** 가 가고, **계좌 입력** 버튼이 있습니다.
누르면 창이 열립니다.

- 계좌번호
- 예금주
- 감사의 말 (안 적어도 됩니다)

보내면 급여 신청 채널(`PAYROLL_CHANNEL_ID`)에 올라가고, 그 안에 **지급 완료** 버튼이 있습니다.
총관리자가 누르면

- 직원에게 DM 으로 지급 완료를 알립니다.
- 신청 채널의 글이 **지급 완료** 로 바뀝니다.
- **지금까지 받은 금액** 이 함께 표시됩니다.

`/지급상태` 로도 볼 수 있습니다.
금액은 적어 주신 글자에서 숫자만 뽑아 더합니다. (`100,000원` -> 100000)

## 송금 요청

```
/송금요청 유저:@손님 얼마:100,000원 기한:3일 내용:제품 값
```

대상자에게 DM 이 갑니다.

```
송금 요청
케이뱅크 888002809240 예금주: `ㅈㅎㅈ`

금액    100,000원
기한    2026-08-12 (수) 오후 01:20
내용    제품 값
안내    위 계좌로 보내신 뒤 아래 버튼을 눌러 주세요.

[보냈습니다]
```

**보냈습니다** 를 누르면 총관리자에게 DM 으로 확인 요청이 갑니다.
같은 내용이 `PAYMENT_LOG_CHANNEL_ID` 채널에도 올라가서, DM 을 닫아 두었어도 확인할 수 있습니다.

```
송금 확인 요청
@손님 님이 보냈다고 했습니다.

[확인됐습니다]  [돈을 받지 못했어요]
```

| 누른 버튼 | 일어나는 일 |
| --- | --- |
| 확인됐습니다 | 로그 채널에 기록이 남고, 보낸 사람에게 확인됐다는 DM 이 갑니다. |
| 돈을 받지 못했어요 | 로그 채널에 미확인으로 남고, 보낸 사람에게 계좌와 함께 **보냈습니다** 버튼이 다시 갑니다. |

미확인은 몇 번이든 반복할 수 있고, 몇 번째인지 기록에 남습니다.
이미 확인 처리된 요청은 다시 눌러도 바뀌지 않습니다.

계좌는 `.env` 의 `PAYMENT_BANK`, `PAYMENT_ACCOUNT`, `PAYMENT_HOLDER` 로 바꿉니다.

## 명령어 사용 권한

명령마다 쓸 수 있는 역할을 정할 수 있습니다.

```
COMMAND_ROLES=송금요청:1111,배당:2222/3333
```

- 여러 명령은 쉼표, 한 명령에 역할 여러 개는 슬래시로 나눕니다.
- 역할을 정한 명령은 **서버 관리 권한이 없어도 그 역할만 있으면** 쓸 수 있습니다.
- 서버 관리자와 총관리자 역할은 언제나 모든 명령을 쓸 수 있습니다.
- 역할을 정하면 그 명령은 목록에서 모두에게 보이고, 실제 판정은 봇이 합니다.
  (디스코드는 기본 노출을 권한 단위로만 정할 수 있어서 그렇습니다.)

바꾼 뒤에는 봇을 다시 켜 주세요.

## 저장 방식

문의 번호, 설정, 제품 모두 **파일에 저장하지 않습니다.**

| 내용 | 어디에 있나 |
| --- | --- |
| 문의 번호 | 열려 있는 채널 이름과 기록 채널의 HTML 파일 이름 |
| 직원 명단 설정, 분야별 직원 | 보관 채널에 봇이 고정해 둔 메시지 |
| 제품과 zip 파일 | 보관 채널에 봇이 올린 메시지 |
| 환영 그림 | 보관 채널에 봇이 올린 메시지 (welcome.png) |
| 초대 코드와 들어온 사람 수 | 보관 채널에 봇이 올린 메시지 |
| 더한 문의 안내 문단 | 보관 채널에 봇이 올린 메시지 |
| 배당 하나하나 | 보관 채널에 봇이 올린 메시지 (고칠 때 그 메시지를 수정) |
| 급여 하나하나 | 보관 채널에 봇이 올린 메시지 |
| 송금 요청 하나하나 | 보관 채널에 봇이 올린 메시지 |

봇을 옮기거나 다시 설치해도 그대로 남습니다.

## 파일 구조

모든 파일은 `bot` 폴더 안에 그대로 들어 있습니다.

```
bot/
  index.js            실행 진입점, 상호작용 라우팅, 슬래시 명령 등록
  config.js           토큰, 이름, 채널/역할 ID, 문의 종류, 문의 시간
  tickets.js          문의 접수와 종료, 번호 정하기
  transcript.js       HTML 기록 생성 (Components V2 컨테이너도 그대로 재현)
  assignments.js      분야 설정, 업무 배당, 기간 조정, 연장, 경고
  payroll.js          급여 안내, 계좌 입력, 지급 완료
  payments.js         송금 요청과 입금 확인
  permissions.js      명령어마다 쓸 수 있는 역할 판정
  reviews.js          별점과 후기 창
  products.js         제품 등록, 전송, 받기
  storage.js          설정과 제품을 디스코드 메시지에 보관
  staff.js            직원 명단과 직책 설정
  welcome.js          서버에 들어온 사람 맞이하기
  invites.js          초대 코드 발급과 초대 기록
  terms.js            이용약관과 A/S 약관 내용, 게시
  notice.js           문의 안내 내용과 게시
  recruit.js          팀별 채용 공고 내용과 게시
  partnership.js      파트너 안내 게시
  components.js       Components V2 컨테이너 만들기 (버튼을 안에 넣는 부분)
  panel.js            패널 게시와 중복 정리
  time.js             한국 시간 서식, 문의 시간 판정
  log.js              로그 출력
  *.js                프테로닥틸 호스팅용 시작 파일 (일반 PC 에서는 필요 없습니다)
  package.json        설치 정보 (discord.js 하나만 씁니다)
  .env.example        .env 를 쓰고 싶을 때 참고할 예시
  README.md
```
