# RoStation 봇

Node.js(discord.js v14)로 만든 디스코드 봇입니다. 문의, 후기, 제품 전달, 안내를 담당합니다.

봇이 보내는 모든 메시지는 **Components V2 컨테이너**로 만들어집니다.
제목, 본문, 구분선, 이미지, 버튼, 드롭다운, 꼬리말이 전부 한 상자 안에 들어갑니다.
(클래식 임베드는 버튼을 안에 넣을 수 없고 항상 임베드 바깥 아래에 붙습니다.)
봇이 만들어내는 문구에는 이모티콘을 쓰지 않습니다.

---

## 문의 시간

```
평일 AM 11:00 ~ PM 06:00
```

이 시간 안에 올라온 문의는 문의 채널에서 **스태프 역할을 부릅니다.**
시간 밖에 올라온 문의는 역할을 부르지 않고, 문의 시간에 답변한다는 안내만 남깁니다.

시간은 한국 시간 기준입니다. `.env` 에서 바꿀 수 있습니다.

## 문의 종류

종류마다 카테고리가 따로 있습니다.

| 종류 | 채널 이름 | 카테고리 설정 |
| --- | --- | --- |
| 통합 문의 | `통합문의-0001` | `TICKET_CATEGORY_GENERAL` |
| 제품 문의 | `제품문의-0001` | `TICKET_CATEGORY_PRODUCT` |
| 파트너 문의 | `파트너문의-0001` | `TICKET_CATEGORY_PARTNER` |

번호는 종류마다 따로 매겨집니다.
채널 이름에 띄어쓰기를 넣으면 디스코드가 하이픈으로 바꾸기 때문에, 채널 이름만 붙여서 씁니다.

**제품 문의와 파트너 문의 카테고리 ID 를 아직 넣지 않았습니다.**
`.env` 에 넣기 전까지는 세 종류가 통합 문의 카테고리를 같이 씁니다. (봇을 켜면 로그로 알려 줍니다.)

## 동작

문의 패널은 봇이 실행될 때 `1535140042652254219` 채널에 자동으로 올라갑니다.
패널이 이미 있으면 지우고 새로 올리므로 재시작해도 하나만 남습니다.

- 패널 컨테이너 **안**에 드롭다운이 있습니다.
- 문의 채널은 작성자 본인과 `1535140290581635162` (스태프) 역할만 볼 수 있습니다.
- 같은 종류의 문의는 한 사람당 하나만 열 수 있습니다.
- 채널 맨 위에 고정되는 컨테이너 **안**에 **문의 닫기** 버튼이 있습니다.
  스태프와 관리자만 쓸 수 있습니다.

## 문의를 닫으면

1. 확인 창이 한 번 뜹니다. (채널 삭제는 되돌릴 수 없기 때문입니다.)
2. 채널의 모든 메시지를 모아 HTML 기록 파일을 만듭니다.
   - 텍스트 (굵게, 기울임, 밑줄, 취소선, 스포일러, 인용문, 코드블록, 제목)
   - 이미지, 동영상, 음성, 그 밖의 첨부파일
   - 링크 (본문에서 자동으로 찾아 목록으로도 정리)
   - 멘션, 커스텀 이모지, 답장 대상, 수정됨 표시, 임베드, 스티커, Components V2 컨테이너
   - 접수 시간, 닫힌 시간, 유지 시간, 작성자, 닫은 사람, 참여자 목록
3. 기록 파일을 `1535140618626670623` 채널에 올립니다.
4. 5초 뒤에 문의 채널을 삭제합니다.

디스코드 첨부파일 링크는 시간이 지나면 만료되기 때문에, 이미지와 동영상은 가능한 한 HTML 파일 안에
직접 넣습니다. 그래서 나중에 파일을 열어도 그대로 보입니다. 용량이 큰 파일은 원본 링크만 남고,
그 사실이 기록 안에 표시됩니다.

## 저장 파일이 없습니다

문의 번호는 별도 파일에 적어 두지 않습니다.
열려 있는 채널 이름과 기록 채널에 올라간 HTML 파일 이름에서 가장 큰 번호를 찾아 다음 번호를 정합니다.
그래서 봇을 옮기거나 다시 설치해도 번호가 이어집니다.

## 실행

이 봇은 exe 파일이 아니라 Node.js 프로그램입니다. 실행 진입점은 `index.js` 입니다.
먼저 [nodejs.org](https://nodejs.org) 에서 **Node.js LTS** 를 설치해 주세요. (18.17 이상이 필요합니다.
개발과 확인은 Node 22에서 했습니다.)

Components V2 를 쓰므로 `discord.js` 는 **14.19.0 이상**이 필요합니다.
`package.json` 에 그렇게 적혀 있으니 `npm install` 만 하면 됩니다.

1. `bot` 폴더에서 라이브러리를 설치합니다. 처음 한 번만 하면 됩니다.

   ```bash
   cd bot
   npm install
   ```

   설치되는 것은 `discord.js` 하나뿐입니다.

2. `config.js` 를 메모장으로 열고, 맨 위 `BOT_TOKEN` 의 따옴표 사이에 봇 토큰을 붙여넣고 저장합니다.

   ```js
   const BOT_TOKEN = '여기에 토큰을 붙여넣으세요';
   ```

3. 실행합니다.

   ```bash
   npm start        # node index.js 와 같습니다
   ```

끌 때는 `Ctrl + C` 를 누르면 됩니다.

### .env 파일을 쓰고 싶다면

토큰을 소스 파일에 두기 싫으면 `bot` 폴더에 `.env` 파일을 만들어도 됩니다.
`.env.example` 을 복사해서 쓰면 편합니다. `.env` 값이 `config.js` 의 `BOT_TOKEN` 보다 우선합니다.

```bash
cp .env.example .env    # 그리고 DISCORD_TOKEN 을 채웁니다
```

별도 라이브러리 없이 봇이 직접 읽으므로 `dotenv` 같은 걸 설치할 필요는 없습니다.

### 토큰 주의사항

`config.js` 에 토큰을 넣었다면 **그 파일을 깃허브에 올리거나 남에게 보내지 마세요.**
토큰이 새면 다른 사람이 봇을 마음대로 조종할 수 있습니다.
이미 샜다면 디스코드 개발자 포털에서 `Reset Token` 을 눌러 새로 발급받으면 됩니다.
소스를 공유할 일이 있다면 `.env` 방식을 쓰는 편이 안전합니다. (`.env` 는 `.gitignore` 에 들어 있습니다.)

### 프테로닥틸(Pterodactyl) 호스팅에 올릴 때

파일은 `bot` 폴더째로 올리지 말고, **`bot` 폴더 안의 내용물을 `/home/container` 바로 아래**에
올려 주세요. `package.json` 과 `index.js` 가 `/home/container/package.json`,
`/home/container/index.js` 가 되어야 합니다.

그리고 패널 **Startup** 탭에서 `MAIN_FILE` 값을 정확히 아래처럼 바꿔 주세요.

```
*.js
```

`index.js` 가 아니라 `*.js` 입니다. 오타가 아닙니다.

이유는 이렇습니다. 많이 쓰이는 Node.js 에그의 시작 명령이 이렇게 되어 있습니다.

```bash
if [[ "${MAIN_FILE}" == "*.js" ]]; then node ... ; else ts-node --esm ... ; fi
```

오른쪽 `"*.js"` 에 따옴표가 붙어 있어서 패턴 비교가 아니라 **글자 그대로의 비교**가 됩니다.
그래서 `MAIN_FILE` 이 `index.js` 면 조건이 항상 거짓이 되고, 봇이 `node` 가 아니라 `ts-node` 로
실행됩니다. 그 `ts-node` 는 컨테이너에 typescript 가 없어서 시작하자마자 아래처럼 죽습니다.

```
TypeError: Cannot read properties of undefined (reading 'fileExists')
    at readConfig (/usr/local/lib/node_modules/ts-node/dist/configuration.js:91:33)
```

`MAIN_FILE` 을 `*.js` 로 두면 조건이 참이 되고, 같이 들어 있는 `*.js` 파일이 `index.js` 를
불러오는 역할을 합니다. 그래서 정상적으로 `node` 로 실행됩니다.

패널에서 **시작 명령(Startup Command) 자체를 고칠 수 있다면** 그게 더 깔끔합니다.
그때는 `MAIN_FILE` 을 `index.js` 로 두고 시작 명령을 아래처럼 바꾸면 됩니다.
(`*.js` 파일은 그냥 두어도 아무 문제 없습니다.)

```bash
/usr/local/bin/node /home/container/index.js
```

### 24시간 켜 두려면

창을 닫으면 봇도 꺼집니다. 항상 켜 두려면 PC를 계속 켜 두거나,
서버 호스팅에 올려서 `pm2` 같은 도구로 실행하는 방법이 있습니다.

```bash
npm install -g pm2
pm2 start index.js --name rostation-bot
pm2 save
```

## 디스코드 개발자 포털 설정

**Bot 탭에서 아래 두 가지를 반드시 켜 주세요.**

- `MESSAGE CONTENT INTENT` - 기록에 메시지 본문을 담는 데 필요합니다. 꺼져 있으면 기록이 빈 내용으로 저장됩니다.
- `SERVER MEMBERS INTENT` - 직원 명단에서 역할별 인원을 세는 데 필요합니다.

## 봇에게 필요한 권한

| 권한 | 쓰이는 곳 |
| --- | --- |
| 채널 보기 / 메시지 보내기 / 링크 첨부 / 파일 첨부 | 패널 게시, 기록 전송 |
| 메시지 기록 보기 | 기록 생성, 번호 확인, 기존 패널 정리 |
| 채널 관리 | 문의 채널 생성 및 삭제 |
| 메시지 관리 | 문의 안내 메시지 고정, 설정 메시지 고정 |
| 모두에게 멘션 | 스태프 역할 호출, 파트너 안내의 모두멘션 |

## 슬래시 명령

전부 서버 관리 권한이 있어야 보입니다.

| 명령 | 설명 |
| --- | --- |
| `/티켓패널` | 문의 패널을 다시 게시합니다. |
| `/이용약관` | 명령을 쓴 채널에 이용약관을 올립니다. |
| `/직원명단` | 명령을 쓴 채널에 직원 명단을 올립니다. |
| `/직원명단설정 추가` | 역할을 직책으로 등록합니다. `역할` `직책` `별` |
| `/직원명단설정 삭제` | 등록한 직책을 뺍니다. `역할` |
| `/직원명단설정 목록` | 등록된 직책을 봅니다. |
| `/파트너쉽` | 파트너 안내를 올립니다. `서버링크` `제목` `소개글` `모두멘션` `사진` |
| `/제품설정 등록` | zip 파일을 제품으로 등록합니다. `이름` `파일` `설명` |
| `/제품설정 삭제` | 등록한 제품을 지웁니다. `제품` |
| `/제품설정 목록` | 등록된 제품을 봅니다. |
| `/제품전송` | 제품을 특정 유저에게 DM 으로 보냅니다. `제품` `유저` |

문의 패널은 봇이 켜질 때 자동으로 올라가므로 `/티켓패널` 은 평소에 쓸 일이 없습니다.

## 이용약관

`/이용약관` 을 쓰면 그 채널에 약관이 올라갑니다.
내용은 `terms.js` 맨 위의 목록을 고치면 바뀝니다.

## 직원 명단

역할마다 직책과 별 개수를 등록해 두면, 그 역할을 가진 사람이 자동으로 명단에 들어갑니다.

```
/직원명단설정 추가  역할:@Head Director  직책:Head Director  별:5
/직원명단설정 추가  역할:@Director       직책:Director       별:4
/직원명단설정 추가  역할:@Manager        직책:Manager        별:2
/직원명단설정 추가  역할:@Secretary      직책:Secretary      별:1
```

`/직원명단` 을 쓰면 이렇게 나옵니다. 별이 많은 직책이 위로 갑니다.

```
[★★★★★]
Head Director - @사람

[★★★★]
Director - @사람

[★★]
Manager - @사람

[★]
Secretary - @사람
```

역할에 아무도 없으면 `공석` 으로 나옵니다.
역할별 인원을 세려면 개발자 포털에서 `SERVER MEMBERS INTENT` 를 켜야 합니다.

## 파트너 안내

```
/파트너쉽 서버링크:https://discord.gg/... 제목:파트너 소개 소개글:... 모두멘션:True 사진:(업로드)
```

명령을 쓴 채널에 컨테이너로 올라갑니다. 안에 사진과 **서버 들어가기** 버튼이 들어갑니다.
`모두멘션` 을 켜면 `@everyone` 이 함께 나갑니다. 봇에게 모두에게 멘션 권한이 있어야 합니다.

## 후기

문의를 닫으면 문의를 남긴 사람에게, 제품을 받으면 받은 사람에게 **DM 으로 후기 요청**이 갑니다.

1. 별점 목록에서 1점부터 5점까지 고릅니다.
2. 고르면 후기를 적는 창이 열립니다.
3. 적어서 보내면 후기 채널(`REVIEW_CHANNEL_ID`)에 올라갑니다.

상대가 DM 을 닫아 두었으면 조용히 넘어갑니다. (로그에는 남습니다.)

## 제품

zip 파일만 등록할 수 있습니다.

```
/제품설정 등록  이름:내 제품  파일:(zip 업로드)  설명:설명글
/제품전송      제품:내 제품  유저:@사람
```

등록하면 봇이 zip 파일을 보관 채널(`STORAGE_CHANNEL_ID`)에 올려 둡니다.
`/제품전송` 을 하면 받는 사람에게 DM 으로 컨테이너가 가고, 그 안에 **제품 받기** 버튼이 있습니다.

**제품 받기** 를 누르면 그때 다운로드 주소를 새로 받아와 **다운로드** 버튼이 있는 화면을 보여 줍니다.
디스코드 첨부 링크는 시간이 지나면 만료되기 때문에, 미리 만들어 둔 주소를 넣지 않고 누를 때마다 새로
받아옵니다. 만료되면 **제품 받기** 를 다시 누르면 됩니다.

제품을 받고 나면 곧바로 제품 후기 요청이 DM 으로 갑니다.

`/제품설정` 과 `/제품전송` 은 `PRODUCT_APPROVAL_ROLE_ID` 역할이나 관리자만 쓸 수 있습니다.

## 저장 방식

문의 번호, 설정, 제품 모두 **파일에 저장하지 않습니다.**

| 내용 | 어디에 있나 |
| --- | --- |
| 문의 번호 | 열려 있는 채널 이름과 기록 채널의 HTML 파일 이름 |
| 직원 명단 설정 | 보관 채널에 봇이 고정해 둔 메시지 |
| 제품과 zip 파일 | 보관 채널에 봇이 올린 메시지 |

봇을 옮기거나 다시 설치해도 그대로 남습니다.

| `TICKET_CATEGORY_GENERAL` | 통합 문의 카테고리 (1535141065160658944) |
| `TICKET_CATEGORY_PRODUCT` | 제품 문의 카테고리 (비어 있으면 통합 문의와 같이 씀) |
| `TICKET_CATEGORY_PARTNER` | 파트너 문의 카테고리 (비어 있으면 통합 문의와 같이 씀) |
| `BUSINESS_START_HOUR` | 문의 시작 시각 (11) |
| `BUSINESS_END_HOUR` | 문의 종료 시각 (18) |
| `BUSINESS_DAYS` | 문의 받는 요일. 0=일 ... 6=토 (1,2,3,4,5) |
| `REVIEW_CHANNEL_ID` | 후기가 올라갈 채널 (없음) |
| `STORAGE_CHANNEL_ID` | 설정과 제품 zip 을 보관할 채널 (없음) |
| `PRODUCT_APPROVAL_ROLE_ID` | 제품을 등록하고 보낼 수 있는 역할 (없음) |
| `TICKET_PANEL_IMAGE_URL` | 패널 안에 넣을 배너 이미지 주소 (없음) |
| `TICKET_DELETE_DELAY_SECONDS` | 기록을 올린 뒤 채널 삭제까지 대기 시간 (5) |
| `TRANSCRIPT_MAX_MESSAGES` | 기록에 담을 최대 메시지 수 (5000) |
| `TRANSCRIPT_INLINE_MAX_BYTES` | HTML 안에 넣을 개별 파일 최대 크기 (2MB) |
| `TRANSCRIPT_INLINE_TOTAL_BYTES` | HTML 안에 넣을 파일 총 용량 (6MB) |

문의 종류를 늘리거나 이름을 바꾸려면 `config.js` 의 `TICKET_TYPES` 를 고치면 됩니다.

## 파일 구조

모든 파일은 `bot` 폴더 안에 그대로 들어 있습니다.

```
bot/
  index.js            실행 진입점, 상호작용 라우팅, 슬래시 명령 등록
  config.js           토큰, 이름, 채널/역할 ID, 문의 종류, 문의 시간
  tickets.js          문의 접수와 종료, 번호 정하기
  transcript.js       HTML 기록 생성 (Components V2 컨테이너도 그대로 재현)
  reviews.js          별점과 후기 창
  products.js         제품 등록, 전송, 받기
  storage.js          설정과 제품을 디스코드 메시지에 보관
  staff.js            직원 명단과 직책 설정
  terms.js            이용약관 내용과 게시
  partnership.js      파트너 안내 게시
  components.js       Components V2 컨테이너 만들기 (버튼을 안에 넣는 부분)
  panel.js            패널 게시와 중복 정리
  time.js             한국 시간 서식, 문의 시간 판정
  log.js              로그 출력
  *.js                프테로닥틸 호스팅용 시작 파일 (일반 PC 에서는 필요 없습니다)
  package.json        설치 정보 (discord.js 하나만 씁니다)
  .env.example        .env 를 쓰고 싶을 때 참고할 예시
  README.md
```
